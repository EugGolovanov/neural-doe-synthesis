# Синтез четырёхплоскостного фазового ДОЭ

Код строит одну фазовую маску 128×128 для восстановления четырёх заданных изображений на разных расстояниях. Начальную фазу предсказывает предобученная нейросеть; затем фаза уточняется через дифференцируемую модель распространения Френеля.

## Метод

```text
Четыре целевых PNG
        ↓
Предобученная U-Net с физическим адаптером
(2 внутренних шага GS+Muon в каждом латентном канале)
        ↓
Начальная фаза 128×128
        ↓
3000 прямых Muon-обновлений фазы по amplitude+SSIM
        ↓
ДОЭ → сохранение и чтение PNG → четыре восстановления → метрики
```

Используется checkpoint сети, обученной на 27 000 примерах за три эпохи. Во время синтеза сеть выполняется один раз, её веса не обновляются. Два внутренних шага адаптера соответствуют обучению; это не число последующих обновлений фазы.

Внешний оптимизатор изменяет непосредственно 16 384 фазовых значения. Его loss объединяет ошибку амплитуды с фиксированной мощностной калибровкой цели и структурную ошибку `0.5 × (1 − SSIM)`. Для SSIM интенсивность каждой плоскости нормируется по её максимуму; градиент проходит через эту нормировку. Внутри внешнего цикла GS не выполняется.

Формулы и численные соглашения: [описание алгоритма](phase_initializer/docs/network_phase.md) и [физическая модель](phase_initializer/docs/doe_physics.md).

## Входы и физические параметры

| Параметр | Значение |
|---|---|
| Цели | Четыре одноканальных PNG, uint8, 128×128 |
| Порядок плоскостей | 24.1, 25.3, 26.5, 27.7 мм |
| Общий ДОЭ | 128×128 фазовых значений |
| Длина волны | 532 нм |
| Шаг пиксела ДОЭ | 10 мкм |
| Освещение | Равномерное, амплитуда 1 |
| Распространение | Одно-FFT Френель на каждую плоскость |
| Вычисления | CPU, float64, один поток, seed 17 |

Цели интерпретируются как интенсивности `uint8 / 255`, без resize, crop или гамма-преобразования. Полностью чёрная целевая плоскость не допускается. Четыре изображения не объединяются в мозаику и не задают освещение ДОЭ.

Выходные шаги сеток различаются: `λz / (128Δ)`. Одинаковый размер массива не означает одинаковый физический размер изображения на всех расстояниях.

## Установка и запуск

Требуются Python 3, PyTorch, NumPy и Pillow:

```bash
python3 -m pip install torch numpy pillow
```

Входной комплект должен находиться здесь:

```text
inputs/network_phase/
├── checkpoint_003.pt
├── manifest.json
├── target_1.png
├── target_2.png
├── target_3.png
└── target_4.png
```

`checkpoint_003.pt` — исходные веса двухшаговой сети из запуска `mixed_ssim_27k_3ep_20261107T100359_750664Z`. Веса включены в репозиторий; обучение заново не требуется. Загружайте только доверенный checkpoint.

Код предобучения на 27 000 четвёрках, параметры, история и точное разбиение сохранены в [pretraining_27k/](pretraining_27k/README.md). Там же приведена команда повторного обучения.

Из корня проекта:

```bash
python3 synthesize_phase.py
```

Для своих четырёх изображений можно передать пути напрямую:

```python
from pathlib import Path
from synthesize_phase import run

run(targets=(
    Path('my_targets/plane_1.png'),
    Path('my_targets/plane_2.png'),
    Path('my_targets/plane_3.png'),
    Path('my_targets/plane_4.png'),
))
```

Короткая проверка всей цепочки с двумя **внешними** обновлениями:

```python
from synthesize_phase import CONFIG, run

run(config={**CONFIG, 'steps': 2, 'save_every': 2})
```

Параметры внешнего оптимизатора явно заданы в `CONFIG` файла `synthesize_phase.py`. Параметры внутреннего GS+Muon берутся из checkpoint; число внутренних шагов фиксировано равным двум.

## Структура кода

| Файл | Назначение |
|---|---|
| `synthesize_phase.py` | Загрузка входов, инференс сети, прямая оптимизация фазы и сохранение запуска |
| `phase_initializer/models.py` | U-Net и двухшаговый физический адаптер |
| `phase_initializer/physics.py` | Френель, интенсивности, калибровка и amplitude+SSIM |
| `phase_initializer/algorithms.py` | GS, направление Muon и внутренний GS+Muon |
| `phase_initializer/evaluate.py` | Экспорт, повторное чтение и Pearson/SSIM |
| `verify_network_phase.py` | Короткие численные проверки |

## Выходные файлы

Каждый запуск создаёт отдельную папку `results/network_phase_<UTC>/`:

```text
initial/                 Начальная маска сети и её восстановления
final/                   Итоговая маска и её восстановления
    phase.npy            Точная непрерывная фаза, радианы, оси y/x
    doe.png              Квантованная фазовая маска
    restored_1.png       Восстановление на 24.1 мм
    restored_2.png       Восстановление на 25.3 мм
    restored_3.png       Восстановление на 26.5 мм
    restored_4.png       Восстановление на 27.7 мм
    intensity.npy        Интенсивности из повторно прочитанной PNG-фазы
    intensity_from_phase.npy
    phase_evaluation.json
summary.json             Метрики до/после, итоговый loss и время
history.jsonl            Loss до каждого обновления, включая четыре плоскости
phase_*.npy              Фаза каждые 100 обновлений
momentum.npy             Конечное состояние Muon
parameters.json          Фактические параметры и хеши входов
environment.json         Версии и среда вычислений
inputs/                  Копии целей и checkpoint
source/                  Снимок использованного кода
```

Фаза для PNG приводится к диапазону `[−π, π)` и кодируется с делителем **255**, не 256: код 0 соответствует −π, код 255 — +π. Точная `phase.npy` сохраняется без квантования.

Итоговые восстановления рассчитываются после повторного чтения `doe.png`. Каждая интенсивность нормируется по собственному максимуму и сохраняется в PNG. Pearson и SSIM вычисляются по повторно прочитанным изображениям, отдельно для всех четырёх плоскостей. Неопределённый Pearson записывается как `null` с причиной. Выбирается последний шаг, а не скрыто отобранный лучший промежуточный результат.

## Проверки и выполненные запуски

Численные проверки:

```bash
python3 verify_network_phase.py
```

Полученные невязки в float64:

| Проверка | Ошибка | Допуск |
|---|---:|---:|
| Сохранение дискретной суммы интенсивности | 1.47×10⁻¹⁶ | 10⁻¹² |
| Направленная производная loss против центральной разности | 3.44×10⁻⁸ | 10⁻⁵ |
| Согласованность двух реализаций SSIM | 4.72×10⁻¹⁶ | 10⁻¹² |

Точное повторное чтение NPY и PNG-экспорт проверены. Начальная фаза выделенной реализации побитово совпала с сохранённым результатом исходной двухшаговой сети.

На первых трёх четвёрках сохранённого test-разбиения выполнены по 3000 внешних обновлений без подбора параметров:

| Индекс примера | Средний SSIM сети | Средний SSIM после уточнения | Худший итоговый SSIM | Время уточнения, с |
|---|---:|---:|---:|---:|
| 0 | 0.167 | 0.493 | 0.316 | 35.9 |
| 1 | 0.048 | 0.396 | 0.251 | 37.1 |
| 2 | 0.089 | 0.488 | 0.209 | 38.0 |

Метрики относятся к PNG-протоколу одно-FFT модели. Время измерено на CPU в один поток, без прогрева; оно включает запись истории и промежуточных фаз, но не финальный экспорт. Точная среда сохранена в `environment.json` каждого запуска.

Сводка: `results/three_test_examples_20261108T141521_943361Z/summary.json`. В каталогах этих трёх запусков дополнительно сохранён `comparison.png`: цели, выход сети и результат уточнения. Полные поплоскостные Pearson/SSIM доступны в `summary.json` соответствующего запуска.
