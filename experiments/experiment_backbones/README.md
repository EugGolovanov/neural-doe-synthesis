# ConvNeXt-Tiny / FNO / axial Mamba-like в физической развёртке

## Постановка и границы

Гипотеза: замена общей CNN-коррекции меняет качество/стоимость синтеза четырёхплоскостного ДОЭ. В новых запусках сравниваются `cnn_convnext_tiny`, `unet_convnext_tiny`, `fno`, `mamba_axial` и отдельный итеративный `gs_muon`. Старые результаты `cnn` и `unet` относятся к прежним компактным сетям и не перезаписываются. Это **не** GS внутри обучаемой развёртки: нейросетевые варианты используют физический градиентный шаг и обучаются Muon; GS + Muon служит baseline. Физика и PNG-протокол не изменены относительно `../experiment_unrolled_cnn`.

Mamba здесь — явно определённая исследовательская axial selective-SSM реализация на PyTorch, **не воспроизведение** Mamba, Vim, VMamba или HoloMamba. Нет fused kernels, patch embedding, RMSNorm и стандартного expansion-блока Mamba. Поэтому сравнение времени характеризует этот код на CPU, не оптимизированные реализации семейств. Полное обучение и превосходство архитектур не проверены.

Из корня репозитория, Python 3.12:

```bash
python -m pip install torch==2.10.0 numpy==2.2.6 pillow==10.4.0
python -m experiments.experiment_backbones.verify
python -m experiments.experiment_backbones.verify_convnext
python -m experiments.experiment_backbones.experiment
```

Проверенное окружение приведено в `verification_report.md`. Полный запуск обучает все четыре модели на трёх seed; reference SSM заметно дороже CNN. Данные генерируются автоматически, скачивания не нужны. Результаты получают новый UTC-каталог `experiments/experiment_backbones/results/backbones_*`; существующий каталог не перезаписывается. Для собственного короткого эксперимента можно вызвать `run_experiment(deepcopy(CONFIG), новый_Path)` из Python, изменив копию словаря, без редактирования исходников.

## Два набора MNIST вместо нескольких seed

```bash
python -m experiments.experiment_backbones.mnist_experiment
```

Этот запуск сравнивает все пять методов на двух наборах MNIST, с фиксированным seed моделей 17. Каждый набор содержит 24/6/6 train/validation/test четвёрок, 10 эпох, K=3, GS + Muon=100 итераций. Одна последовательность PCG64(2026) задаёт permutation официальных train, затем test; для наборов берутся непересекающиеся срезы. Проверяется отсутствие повторяющихся исходных пикселей между всеми выборками обоих наборов. Все методы внутри набора получают одинаковые цели, начальную фазу и порядок обучения. Различие наборов не является оценкой разброса по инициализациям модели.

MNIST загружается с `https://storage.googleapis.com/cvdf-datasets/mnist/`; исходные IDX, URL и SHA-256 сохраняются в корне запуска. Preprocessing явно отличается от синтетического: Pillow BILINEAR 28×28 → 128×128, uint8 grayscale, без порога, гаммы и дополнительной нормировки. Это подготовка MNIST, не автоматическое исправление произвольного входного PNG. Точные индексы сохраняются в `suite_configurations.json` и конфигурациях отдельных наборов, метки и хеши — в manifests.

Результаты: `results/mnist_two_datasets_<UTC>/dataset_{1,2}/`; `status.json` в корне создаётся только после успешного завершения обоих наборов. Время SSM относится к последовательной CPU reference реализации. Запуск может быть продолжительным.

## Общий алгоритм

Вход: float32 `[B,4,128,128]`, интенсивности PNG/255, порядок плоскостей 24.1/25.3/26.5/27.7 мм. Фаза: `[B,1,128,128]`, радианы. CPU, B=1, один поток. Френель: λ=532 нм, шаг ДОЭ 10 мкм; см. `../../docs/doe_physics.md`.

Для всех моделей контекст `C=SiLU(Conv3x3(T))` вычисляется один раз. На каждом из K=3 шагов:

- `g = grad_phi mean_planes_pixels((I/(max(I)+1e-12)-T)^2)`;
- `v = phi - 1000*g`;
- `S = [cos(v), sin(v), g/sqrt(mean_pixels(g²)+1e-16), C]`;
- `phi = v + 0.1*tanh(backbone(S))`.

Веса общие по шагам; выходная голова нулевая при инициализации. Полный градиент через физические градиенты с `create_graph=True`, non-reentrant checkpoint; нет усечения при обучении. Detach между шагами применяется только при инференсе. Это остаточная коррекция, не доказанный proximal-оператор. Контекст целей — условные признаки, а не отождествление разных физических сеток.

## Архитектуры и Muon

- `cnn_convnext_tiny`: полный backbone ConvNeXt-Tiny, последний масштаб 768×4×4 → Conv1x1 до 8 каналов → SiLU → bilinear upsampling до 128×128 → нулевая Conv3x3-голова → tanh; без skip-связей.
- `unet_convnext_tiny`: тот же backbone; каждый из четырёх масштабов проецируется Conv1x1 в 8 каналов, затем декодируется от 4×4 до 32×32 через bilinear upsampling, concatenation skip и Conv3x3 + SiLU; после upsampling до 128×128 — нулевая Conv3x3-голова и tanh. Везде `align_corners=False`.

Оба backbone имеют глубины `[3,3,9,3]`, ширины `[96,192,384,768]`, stem Conv4x4 со stride=4, три downsampling Conv2x2 со stride=2. Блок: depthwise Conv7x7 (zero padding=3), LayerNorm по каналам (epsilon=1e-6), pointwise MLP с expansion=4 и GELU, LayerScale=1e-6, residual. Pointwise Conv1x1 эквивалентны поканальным Linear. Stochastic depth отключён; предобученных весов, загрузок и новых зависимостей нет. Сохранены bias свёрток и affine LayerNorm. Классификатор и pooling удалены, входной stem принимает `width+3=11` каналов состояния, а не RGB; это адаптация ConvNeXt-Tiny для плотного выхода, не ImageNet-модель без изменений. Контекст целей по-прежнему вычисляет Conv3x3 + SiLU один раз, а ConvNeXt обрабатывает состояние на каждом шаге. Число параметров: 27 837 384 / 27 846 216 соответственно; на CPU обучение и checkpoints существенно дороже прежних сетей. Ширина 8 в конфигурации теперь относится к контексту и декодеру, не к backbone.

Остальные архитектуры:
- FNO: ширина 4, два спектральных блока, m=4. `rfft2/irfft2(norm='ortho')`, строки `0,…,m-1,H-m+1,…,H-1`, столбцы `0,…,m-1`. Нулевая колонка явно проецируется на эрмитову симметрию; Nyquist-колонка исключена. Веса `[out,in,2m-1,m,2]` хранят real/imag. Локальная ветвь Conv1x1 и GELU; без padding признаков, координат и дополнительной Conv3x3 ветви. Периодический FFT-базис применяется только к признакам.
- Axial Mamba-like: ширина 8, два блока, 4 состояния на канал. Conv1x1 разделяет вход и gate; depthwise Conv3x3 с zero padding и SiLU готовит вход u. Общий SSM независимо сканирует строки и столбцы вперёд/назад, с нулевым состоянием на каждой линии. Четыре результата усредняются, умножаются на SiLU(gate), проходят Conv1x1 и residual-add. Нет соединения конца строки с началом следующей.

SSM использует `A=-exp(log_a)`, начальные `log_a[c,s]=log(s+1)`, `D=1`, `delta=softplus(W_delta*u-3)`, `[B_t,C_t]=W_bc*u`. Рекурсия:

```
h_t = exp(delta_t*A)*h_(t-1) + delta_t*B_t*u_t
y_t = sum_states(C_t*h_t) + D*u_t
```

Это экспоненциальное обновление однородной части и delta-scaled вход, не точная ZOH-дискретизация входного члена. Устойчивость полного обучаемого блока не гарантируется отрицательным A.

Все параметры вещественные; каждый параметр с ≥2 осями представляется матрицей `[first_axis, product(other_axes)]`. В ConvNeXt bias, affine-параметры LayerNorm и LayerScale хранятся как `[channels,1]`, а в forward разворачиваются в обычные поканальные векторы; они получают тот же Muon, не скрытый Adam/SGD. Это выбранное правило оптимизации векторных параметров, а не стандартный рецепт обучения ConvNeXt. Нормировка Muon меняет масштаб обновления относительно малого начального LayerScale; learning rate для новой архитектуры ещё не подобран. Остальные сети по-прежнему без bias. Это касается spectral real/imag весов и `log_a`; `D` хранится как `[channels,1]`. Матрица транспонируется, если строк больше столбцов. Затем применяется существующий Muon с постоянным состоянием импульса: lr=0.01, momentum=0.95, Nesterov, 5 Newton–Schulz шагов с коэффициентами (3.4445, -4.7750, 2.0315), epsilon=1e-12, scale=1, weight decay=0. Нет скрытого Adam для нематричных параметров. Такое уплощение спектральных весов — выбранное экспериментальное правило, не комплексная ортогонализация по модам.

GS + Muon: 100 итераций, lr=0.1, остальные параметры Muon те же; формулы проекций и правило фазовой ветви см. `../experiment_gs_muon/README.md`. Начальная случайная фаза одинакова у всех методов данного seed.

## Данные и честность сравнения

Существующий генератор `experiment_unrolled_cnn/data.py`: независимые гауссовы пятна, полосы и косинусные решётки; интенсивности округляются в PNG и читаются обратно. Train/validation/test=24/6/6 четвёрок, data_seed=2026; отдельный PCG64 от `[data_seed, object_id]` для каждого объекта. Нет повторяющихся объектов между выборками, SHA-256 проверяется и сохраняется. Это малый диагностический синтетический набор, не оценка обобщения на реальные изображения.

Seed 17/29/43; 10 эпох, batch=1; одинаковый порядок train для всех моделей задаётся torch seed `seed+100000`, отдельно от инициализации весов. Checkpoint выбирается только по среднему validation loss, включая необученный epoch=0. Test не используется для выбора. Ширины, число параметров и вычислительные бюджеты **не уравнены**, lr общий, не подобран по validation. Сравнение проверяет фиксированные конфигурации, не лучший возможный результат каждого семейства.

Время обучения включает validation и checkpoint I/O. Инференс batch=1 измеряется после полного прогрева данной модели, экспорт исключён. GS прогревается одной итерацией и выполняется один раз на пример/seed (в новых запусках файлы лежат внутри каталога `cnn_convnext_tiny`; в старых — `cnn`). Его per-instance оптимизация входит во время. CPU не требует синхронизации ускорителя. Peak memory не измеряется, статус сохранён явно. Фиксированный seed не обещает побитовую идентичность на другой платформе.

## Файлы и чтение результатов

- `parameters.json`, `comparison_source_sha256.json`, `source/`: фактическая конфигурация, физика, версии, Git revision/status/diff и копии используемых исходников/документов, включая незакоммиченные файлы;
- `data/`, `data_manifest.json`: исходные PNG, параметры генерации, split и SHA-256;
- `seed_*/initial_phi.npy`: общая начальная фаза;
- `seed_*/<model>/training_history.json`, `training_summary.json`, `best.pt`, `last.pt`: loss по плоскостям, нормы градиентов, время, размер модели, веса и финальное состояние Muon/RNG;
- `seed_*/<model>/test/<index>/<method>/`: непрерывная фаза, `doe.png`, прочитанные обратно восстановления PNG, сырые интенсивности, метрики и эффект квантования;
- `summary.json`: строки по seed, методу и тестовому примеру, восемь попарных Pearson/SSIM, время, параметры и число распространений.

Итоговые метрики всегда рассчитаны после реального PNG-экспорта/чтения; неопределённый Pearson остаётся null. Сравнивать следует все примеры и seed, а не только одно среднее. Код не делает автоматических выводов о превосходстве.
