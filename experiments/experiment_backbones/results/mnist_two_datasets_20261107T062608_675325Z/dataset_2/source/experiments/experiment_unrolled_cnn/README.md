# Компактная CNN-развёртка с обучением Muon

## Постановка и статус

Реализован пункт 4: общая CNN-коррекция в K физических шагах, обучение через всю развёртку и сравнение с GS + Muon на отложенных синтетических целях. Гипотеза: обученная коррекция улучшает компромисс PNG-качества и времени относительно итеративного синтеза. Превосходство Muon принимается как исходное заключение пользователя для дальнейшей работы; этот эксперимент не повторяет сравнение оптимизаторов и сам по себе его не доказывает.

Полное обучение не является частью численной проверки. Наличие реализации не означает преимущества CNN, физической валидации или достижения порога качества. Реализация исследовательская, не воспроизведение статьи. Это компактная CNN, не U-Net; прямой U-Net-контроль сюда не входит.

## Запуск из корня репозитория

Python 3.10+; зависимости прежние:

```sh
python3 -m pip install torch numpy Pillow
python3 -m experiments.experiment_unrolled_cnn.verify
python3 -m experiments.experiment_unrolled_cnn.experiment
```

Последняя команда запускает полный предварительный эксперимент: 3 seed, 10 эпох, 24/6/6 четвёрок train/validation/test. Точные значения находятся в `experiment.py:CONFIG`. Повторение сохранённой версии: перейти в каталог `source` результата и выполнить ту же команду модуля, имея Git-репозиторий для записи provenance. Для повторения с иной явной конфигурацией можно вызвать `run_experiment(config, output)` из Python; существующий output отвергается.

## Предварительный запуск на MNIST

```sh
python3 -m experiments.experiment_unrolled_cnn.mnist_experiment
```

Команда загружает оригинальные IDX MNIST с `https://storage.googleapis.com/cvdf-datasets/mnist/` без torchvision; нужны доступ к сети и около 12 МБ для сжатых исходников. URL, SHA-256 и исходные gzip сохраняются в результате. Формат IDX и размеры проверяются. Контрольные суммы фиксируют полученные данные, но не являются независимой проверкой подлинности источника.

Преобразование согласовано явно: исходные полутоновые uint8 28×28 масштабируются Pillow BILINEAR до 128×128 и сохраняются в PNG L, без порога, гаммы, нормировки по максимуму и смены полярности. Это подготовка MNIST к входному контракту ТЗ, а не изменение физического оператора или обработки уже подготовленных входов.

Seed данных 2026 задаёт `numpy.default_rng(seed).permutation(60000)`: первые 96 исходных изображений образуют 24 train-четвёрки, следующие 24 — 6 validation-четвёрок. Группировка по четыре после разбиения, без повторного использования объектов. Test — одна четвёрка из официальной test-части: первое вхождение каждой цифры 0,1,2,3 соответственно расстояниям 24,1/25,3/26,5/27,7 мм. Индексы, метки и хеши сохраняются; дубликаты PNG отклоняются. Метки цифр не подаются в сеть.

Обучение с нуля, seed=17, 10 эпох; остальные параметры CONFIG неизменны. Выбор лучшей эпохи только по validation. Baseline GS + Muon использует ту же начальную фазу и 100 итераций. Это небольшой предварительный запуск на одном seed и одной тестовой четвёрке, не оценка всего MNIST. До полного вывода о качестве нужны больше тестовых объектов и seed. Запуск явно запрошен пользователем; ограничения физической валидации из раздела проверок сохраняются.

Выход — новый `results/mnist_<UTC>`. `seed_17/preview.png` показывает три строки: цели, CNN, GS + Muon, без дополнительного растяжения яркости. Для каждого метода в `seed_17/test/0000/<method>/` находятся одна общая `doe.png` и четыре `restored_*.png`, сырые интенсивности и метрики. Две маски в сравнении относятся к двум разным методам, не к разным плоскостям.

## Метод и интерфейсы

CPU, один поток, batch=1; float32/complex64 для обучения и оптимизации, float64/complex128 для итогового экспорта и метрик. `target: [B,4,128,128]` — интенсивности PNG/255 без гаммы, каналы z=24,1/25,3/26,5/27,7 мм; `phi: [B,1,128,128]` — радианы, строки y, столбцы x. Фаза не ограничена внутри алгоритма; оборачивание только при экспорте. λ=532 нм, Δ=10 мкм. Физика и экспорт импортируются из соседнего GS-эксперимента, не копируются и не меняются.

Для каждого seed генерируется одна равномерная фаза [-π,π), сохраняемая в `initial_phi.npy`; она общая для всех примеров данного запуска и обоих методов. Случайная фаза не является обучаемым параметром.

Точно по разделу 4 архитектурного документа:

1. C = SiLU(Conv3×3(T)), 4→8 каналов, один раз на пример.
2. g = ∂L_data/∂phi; в batch градиент считается от суммы индивидуальных средних по плоскостям, поэтому его масштаб не зависит от B.
3. v = phi − eta·g, eta=1000 фиксировано, не обучается.
4. S = [cos(v), sin(v), g/sqrt(mean(g²)+epsilon_g²), C], epsilon_g=10⁻⁸.
5. phi ← v + 0,1 tanh(D(S)).

D: Conv3×3(11→8), SiLU, Conv3×3(8→8), SiLU, Conv3×3(8→1). Все свёртки без bias; последнее ядро нулевое, остальные используют стандартную инициализацию PyTorch Conv2d (uniform ±1/sqrt(fan_in)). Веса общие для K=3 шагов. Zero-padding=1 применяется только к признакам, не к физическому оператору. Условные каналы разных выходных сеток — признаки, а не физически совмещённые поля.

Фиксированный eta — частный случай положительного шага раздела 4; softplus-параметры не обучаются. Muon обновляет **веса CNN**, а не заменяет физический шаг градиентного спуска внутри развёртки. Это не развёртка GS + Muon. Произвольные detach, нормировки физического градиента, регуляризация, weight decay и квантование в обучении отсутствуют. Loss: MSE I/(max I+10⁻¹²) против T с производной через максимум.

Обучение использует `create_graph=True`, включая производные градиента и RMS-признака через все шаги. Каждый полный шаг проходит non-reentrant checkpointing. Граф не усекается. На инференсе вычисляется только градиент по текущей фазе, граф предыдущего шага удаляется; вычисление выполняется с включённым autograd даже при eval. В точках смены максимума loss кусочно-гладкий.

## Muon для CNN

Единственные параметры — ядра размерности 4; векторов, bias и обучаемых скаляров нет. Ядро представляется матрицей [out,in·ky·kx]; если строк больше столбцов, матрица транспонируется перед Newton–Schulz и обратно после него. Состояние momentum имеет ту же ориентацию. Используется существующая реализация `muon_direction`:

m ← 0,95m+0,05g; h ← 0,05g+0,95m; X ← h/(||h||F+10⁻¹²); пять шагов X ← aX+(bXXᵀ+c(XXᵀ)²)X с (a,b,c)=(3,4445;−4,7750;2,0315). W ← W−0,01X, масштаб=1, weight decay=0. Импульс сохраняется между batch и эпохами, сбрасывается для нового seed. Adam/fallback отсутствует.

eta, gamma, ширина, K и lr — явно заданные предварительные настройки, не результат подбора по test. Выбор checkpoint, включая исходную модель эпохи 0, происходит только по среднему validation loss. Baseline: GS + Muon, 100 шагов, lr=0,1, остальные настройки Muon те же.

## Данные и сравнение

`data.py` генерирует гауссовы пятна, ограниченные полосы и плотные синусоидальные интенсивности; параметры приведены в коде и сохраняются для каждого объекта. NumPy PCG64 получает SeedSequence([data_seed, object_id]); object_id глобально уникален между разбиениями. Четыре плоскости содержат отдельные объекты. Классы повторяются между выборками, но объекты и PNG не повторяются; проверяется уникальность SHA-256. Это небольшой диагностический набор, не оценка обобщения на реальные изображения или новые классы.

PNG сохраняются и перечитываются до обучения; все параметры объектов, принадлежность к split и SHA-256 — в `data_manifest.json`. Разбиение одинаковое для трёх seed обучения. Test не участвует ни в выборе эпохи, ни в обновлении весов.

Время обучения (с validation и checkpoint-записью), CNN-инференса и per-instance GS-оптимизации записывается отдельно. Перед каждым тестовым примером прогревается полный CNN-инференс и одна итерация baseline. CPU не требует CUDA-синхронизации; измерения однократные, без заявления о точном выигрыше задержки. Baseline-таймер включает вычисление диагностической истории, CNN-таймер — нет. Экспорт исключён из обоих таймеров. Пиковая память не измеряется и отмечается null.

Бюджеты различаются: CNN — 8K распространений, GS + Muon — 16×100 плюс диагностические 4×101; CNN дополнительно оплачивает обучение и свёртки. Это сравнение точек качества/стоимости, не одинакового бюджета. Графики и вывод о превосходстве CNN автоматически не строятся.

## Результаты

Новый каталог `results/cnn_<UTC>` содержит фактическую конфигурацию, версии Python/torch/numpy/Pillow, платформу, Git-ревизию/status/diff, исходники обоих используемых модулей и документы с SHA-256, входные PNG и split. Для каждого seed сохраняются история loss по плоскостям и нормы градиента, `best.pt`, `last.pt` (включая momentum и RNG), начальная фаза, время и результаты каждого тестового примера.

`summary.json` содержит четыре Pearson и четыре SSIM после повторного чтения `doe.png` и восстановленных PNG, времена, число распространений и loss по плоскостям до/после квантования. Рядом сохраняются непрерывная фаза, маска, четыре восстановления, сырые интенсивности и сетки. Неопределённый Pearson остаётся null со статусом. Сравнивать отдельные примеры/плоскости и разброс трёх seed, не только среднее.

Детерминированные операции включены; seed PyTorch и NumPy записаны. Побитовое совпадение между версиями и платформами не гарантируется. Снимок содержит все исполняемые зависимости эксперимента; для проверки provenance Git необходим, сторонние библиотеки устанавливаются отдельно.

## Проверки и ограничения

`verify.py` в float64 проверяет градиенты CNN через два физических шага центральной разностью (относительная ошибка <10⁻⁴ хотя бы для одного h=10⁻³/10⁻⁴/10⁻⁵), совпадение градиентов checkpoint/non-checkpoint (max abs <10⁻¹¹), независимость фазы от размера batch (<10⁻¹¹ рад), мощность (<10⁻¹² относительной ошибки) и производную общей фазы (<10⁻¹² относительно L1-нормы градиента). Допуски учитывают float64, центральную разность и кусочную гладкость max; выводятся сами ошибки. Затем выполняется одна smoke-эпоха на трёх объектах с validation/test по одному примеру, сохранением и чтением модели и PNG во временном каталоге.

Эти проверки не заменяют полный протокол физической валидации: сопряжённость, аналитический градиент, уточнение физических пикселей и независимое распространение здесь не проверяются. Smoke-тест не подтверждает качество обученной модели. Полный эксперимент нужно выполнить и отдельно проанализировать до выводов о CNN.
