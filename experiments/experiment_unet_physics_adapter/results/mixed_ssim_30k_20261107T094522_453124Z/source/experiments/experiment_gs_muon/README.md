# Проверка GS + Muon

Для дальнейшей работы превосходство Muon принято как исходное заключение пользователя; повторное сравнение оптимизаторов не планируется. Ниже сохранены условия и ограничения именно исторического запуска, без изменения его измерений. Следующий эксперимент: [CNN-развёртка с обучением Muon](../experiment_unrolled_cnn/README.md).

Команды ниже выполняются из корня репозитория. Код и результаты этого завершённого сравнения находятся в `experiments/experiment_gs_muon/`. В дальнейших методах принят Muon; Adam и чистый GS здесь сохранены как исторические контроли, а не как будущие варианты по умолчанию.

## Гипотеза и статус

Дополнительная Muon-коррекция после многоплоскостного GS улучшает качество относительно GS и GS + Adam при сопоставимых затратах. Это исследовательский гибрид, не воспроизведение статьи и не гарантия сходимости. Первый запуск — предварительный, без подбора параметров и без утверждений об обобщении.

## Запуск

Python 3.10+ с `torch`, `numpy`, `Pillow`:

```sh
python3 -m pip install torch numpy Pillow
python3 experiments/experiment_gs_muon/verify_muon.py
python3 experiments/experiment_gs_muon/experiment.py
```

Проверки не повторяют физическую валидацию: неподвижная точка GS на достижимой цели (ошибка комплексного поля <10⁻¹⁰), направленная производная loss вдоль Muon (относительная ошибка <10⁻⁵ хотя бы для одного из трёх шагов), нулевой градиент, тождественный SSIM (<10⁻¹²) и неопределённый Pearson постоянной цели. Допуски учитывают float64 и ошибку центральной разности; тесты не доказывают преимущество гибрида.

Фактические версии сохраняются. CPU, float64/complex128, один поток, batch=1, 100 итераций, seed 17/29/43. Детерминированные операции PyTorch включены; побитовое совпадение между платформами не гарантируется. `CONFIG` в `experiment.py` содержит параметры запуска; копия исходников и фактические параметры сохраняются в новом каталоге `experiments/experiment_gs_muon/results/gs_muon_<UTC>` без перезаписи. Снимки исходников прежних запусков сохранены неизменными; их старые пути относятся к структуре до переноса.

## Данные

Три аналитически заданные четвёрки: гауссовы пятна, полосы, плотные синусоидальные интенсивности. Формулы находятся в `synthetic_targets`; данные квантуются в uint8 без гаммы. Каналы соответствуют расстояниям 24,1/25,3/26,5/27,7 мм. Сохраняются исходные PNG и SHA-256. Это диагностические примеры, не train/validation/test. До подбора параметров и итогового сравнения нужен отдельный validation/test по новым объектам.

## Точный GS-шаг

Пусть F — центрированная ненормированная FFT, d_j — входная квадратичная фаза, s_j=Δ²/(λz_j). Используется A_j=s_j F diag(d_j). Выходная квадратичная и общая фазы опущены: для интенсивности это эквивалентно физическому оператору, а в амплитудной проекции и обратном ходе эти множители сокращаются. Никакой физический padding не применяется.

1. u=exp(i phi), v_j=A_j u.
2. Целевая амплитуда a_j=sqrt(T_j N⁴ s_j² / sum(T_j)); её дискретная мощность равна мощности v_j.
3. v'_j=a_j exp(i arg(v_j)); arg(0)=0 по соглашению PyTorch.
4. b_j=conj(d_j) F⁻¹(v'_j/s_j), b=¼ sum_j b_j.
5. phi_GS=phi+arg(b exp(-i phi)). При b=0 обновление фазы равно нулю.

Это одновременное равновесное усреднение четырёх обратных полей, а не последовательный GS и не необмасштабированная сумма евклидовых сопряжённых операторов. Чёрные цели явно отклоняются: нормировка целевой амплитуды по мощности для них не определена. GS и обучающий loss имеют различные ограничения, поэтому GS не обязан уменьшать loss.

## Коррекция

После GS вычисляется градиент g физического loss раздела 8 `architecture_design.md`; epsilon=10⁻¹², производная проходит через максимум. Ветвь phi_GS выбирается ближайшей к предыдущей фазе. Внутри итераций фаза не оборачивается, weight decay отсутствует. Состояния оптимизаторов сохраняются после GS и сбрасываются для каждой пары «пример, seed».

Вариант Muon определён здесь полностью, без зависимости от версии внешнего optimizer:

- m ← βm+(1−β)g, β=0,95, начальное m=0;
- h=(1−β)g+βm (выбранное Nesterov-соглашение);
- X=h/(||h||_F+10⁻¹²);
- пять шагов: A=XXᵀ; X ← aX+(bA+cA²)X;
- (a,b,c)=(3,4445; −4,7750; 2,0315);
- phi ← phi_GS−0,1X, дополнительный масштаб равен 1.

Коэффициенты задают приближённое спектральное преобразование, не точную SVD-поляризацию. Ортогональность результата и спуск не гарантируются; вычисления выполняются в float64, не bfloat16. Это явно заданная Muon-подобная реализация для эксперимента, а не заявление о точном воспроизведении конкретной библиотеки. Версия реализации фиксируется сохранённым `algorithms.py`.

Контроль GS + Adam: PyTorch Adam, lr=0,01, betas=(0,9;0,999), eps=10⁻⁸. Значения lr предварительные, не результат равного бюджета подбора. Поэтому различие качества в этом запуске не доказывает превосходства оптимизатора.

`history.json` содержит loss до начала, после GS и после коррекции, RMS коррекции и скалярное произведение градиента с направлением вычитания. Для Muon направление без lr, для Adam — фактическое смещение с lr; сравнивается знак, не абсолютная величина. Отрицательный знак означает направление локального подъёма. Даже положительный знак не гарантирует снижения при конечном шаге.

## Оценка и стоимость

`doe.png` повторно читается; четыре восстановления и метрики рассчитываются по квантованной фазе. Pearson и SSIM сравнивают исходные и повторно прочитанные восстановленные PNG. SSIM: float64, гауссово окно 11×11, sigma=1,5, population covariance, полные окна, data_range=1, K1=0,01, K2=0,03. Для постоянного изображения Pearson=null с причиной. Сохраняются сырые интенсивности, максимумы и шаги сеток; непрерывная фаза сохраняется отдельно.

GS требует 8 распространений на итерацию, гибрид — 16; диагностический loss добавляет 4 на итерацию и 4 в начале. Итоговый экспорт добавляет ещё 4 вне таймера. Время включает диагностические loss и хранение истории, но исключает экспорт и запись на диск. Перед каждым измерением выполняется одна прогревочная итерация с отдельным состоянием. Сравнение по одинаковому числу итераций не является сравнением равных затрат: использовать историю, число распространений и время. Для уверенного сравнения времени нужны дополнительные повторы и более длительный прогрев.

В `summary.json` — результаты каждого случая/seed/метода, восемь метрик и время, без скрытого усреднения. Проверять разброс и отдельные плоскости; для подтверждения гипотезы нужны отдельная валидация lr, новые цели и сравнение при равных бюджетах. Fienup не реализован: его вариант пока не определён.
