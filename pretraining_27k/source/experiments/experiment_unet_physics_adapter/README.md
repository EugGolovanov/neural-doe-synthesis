# U-Net с GS + Muon внутри LoRA-like адаптера

Реализация запроса на физический алгоритм **внутри** адаптерной ветки, а не постобработку выхода U-Net. Это новая исследовательская конструкция, не воспроизведение статьи и не обычная LoRA. Гипотеза: физическая ветка в декодере полезнее столь же низкоранговой линейной ветки; качество и преимущество пока не проверены.

## Формула

После двух уровней encoder/decoder со skip-конкатенациями получаем признаки `h: [batch,C,128,128]`. На полной сетке ДОЭ:

```
p = A h
q[b,k] = GS_Muon(p[b,k], target[b], K)
h_out = W h + (alpha/r) B q
phi = head(h_out)
```

`W: [C,C]`, `A: [r,C]`, `B: [C,r]` — обучаемые матрицы 1×1-свёрток без bias. Каждая из r карт p интерпретируется как отдельная начальная фаза в радианах, все решают одну задачу по четырём целевым интенсивностям. B смешивает решённые карты обратно в признаки. Финальная фаза получается головой U-Net; она не обязана совпадать с одной из латентных фаз.

Эквивалентная запись:

`h_out = (W + alpha/r * B A) h + alpha/r * B (GS_Muon(Ah,T) - Ah)`.

Таким образом присутствуют и низкоранговое смешивание матриц, и нелинейная физическая коррекция **внутри** той же ветки. В отличие от линейной LoRA, всю ветку нельзя слить в постоянную матрицу для инференса. Rank ограничивает канал адаптера, но не ранг нелинейного отображения по пространственным координатам.

W инициализируется единичной матрицей, A — стандартной случайной инициализацией Conv2d PyTorch, B — нулём. Сначала выход совпадает с U-Net без добавки; на первом обновлении градиент A нулевой, после обновления B он появляется. Основа и адаптер обучаются совместно со случайной инициализации. Это явное отличие от этапа адаптации замороженной обученной основы из `docs/architecture_design.md`, выбранное для текущего запроса; случайная основа не замораживается.

## Физика и производные

Переиспользуются `experiment_gs_muon/physics.py`, `gs_step` и `muon_direction`, без изменения одно-FFT оператора, нормировки loss и параметров физики. Каждая итерация: GS с мощностно согласованными амплитудами → физический loss → его градиент по фазе → Nesterov/Newton–Schulz Muon → обновление фазы. Импульс сохраняется между K итерациями, но отдельный для каждой карты и каждого примера; между вызовами forward не сохраняется.

В отличие от исторического per-instance runner, в обучении нет detach и обновлений под no_grad: `create_graph=True` обеспечивает полную производную через градиент loss, momentum и Newton–Schulz. GS использует ближайшую фазовую ветвь, исходное соглашение `angle(0)=0`; в нулях поля и на разрывах ветвей гладкость не гарантируется. Нормировка по максимуму также негладкая при равных максимумах. Не добавляются clamp, STE и регуляризаторы.

Вход: конечные интенсивности [batch,4,128,128] в [0,1], порядок плоскостей 24.1, 25.3, 26.5, 27.7 мм; оси y,x. Полностью чёрная плоскость отклоняется, как в GS baseline. Выход: непрерывная вещественная фаза [batch,128,128] в радианах, без tanh; перед PNG применяется существующий протокол приведения фазы и квантования. Для проверки используются float64/complex128; float32 поддерживается операциями, но здесь не проверен. Padding=1 с нулями касается только признаков; физическая сетка не расширяется. Upsampling nearest относится только к признакам U-Net, не к целям и не к физическим полям.

Внешний Muon обучает все ядра как матрицы [out,in*ky*kx], транспонируя при out>in*ky*kx, с масштабом 1, без weight decay. Его импульсы отдельны от внутреннего Muon. Полные параметры обоих Muon, K=2, rank=2, alpha=2 и width=8 находятся в `experiment.py`. Они не подбирались на validation.

## Использование

Из корня репозитория, Python 3.12 и PyTorch 2.10 (проверенные версии):

```sh
python -m pip install torch==2.10.0
python -m experiments.experiment_unet_physics_adapter.verify
```

Команда выводит JSON с численными ошибками и завершится исключением при нарушении допусков. Файлы результатов не перезаписывает. Проверка использует синтетическую случайную четвёрку с seed=17; это не train/validation/test и не оценка качества.

Для включения в цикл обучения:

```python
import torch
from experiments.experiment_unet_physics_adapter.experiment import CONFIG, build_model, train_step
from experiments.experiment_unrolled_cnn.algorithms import initial_momenta

torch.manual_seed(CONFIG['seed'])
model = build_model(CONFIG)
momenta = initial_momenta(model)
# target: заранее подготовленный torch.float64 [batch,4,128,128] на CPU.
# Для каждого batch: loss = train_step(model, target, momenta, CONFIG).
```

Инференс: `model.eval()` и `with torch.no_grad(): phi = model(target)`; внутренний autograd временно включается для Muon. `torch.inference_mode()` отклоняется явно. Сейчас даже инференс строит полный внутренний граф; это прозрачная, но не оптимизированная по памяти реализация. Стоимость физики растёт как batch × rank × K.

Для датасетного обучения добавлен `train_mnist.py`, запускаемый из корня:

```sh
python -m pip install numpy pillow
python -m experiments.experiment_unet_physics_adapter.train_mnist
```

Runner загружает официальный MNIST и явно готовит 10000 обучающих одноканальных PNG 128×128 (2500 четвёрок), ещё по 400 PNG для validation/test. Изменение размера — документированная подготовка MNIST, не скрытая коррекция входов модели; исходные 28×28 не подаются как входы по ТЗ. Разбиение выполняется до группировки, дубликаты пикселей после подготовки исключаются между всеми выборками. В каждой четвёрке четыре независимых изображения соответствуют четырём расстояниям ТЗ.

Эффективный batch — 256 отдельных PNG, то есть 64 четвёрки; последняя группа — 4 четвёрки (16 PNG). В текущем запуске градиенты среднего loss накапливаются микробатчами по 16 четвёрок, один внешний Muon update на эффективный batch (четыре микробатча; последний неполный batch обрабатывается без дополнения). Это не физический batch=256 четвёрок. В сети нет BatchNorm/dropout, накопление эквивалентно совместному batch с точностью округления. На двух примерах float64 измерена максимальная разность градиентов 2.845e-16 (допуск 1e-10).

Текущий `RUN`: 50 полных эпох с нуля, MPS/float32, микробатч=16, один CPU-поток, seed=17, разбиение/перемешивание seed=2026; остальные параметры — `RUN` и `CONFIG`. Завершённый исторический запуск одной эпохи CPU/float64 сохранён вместе со снимком его кода. При отсутствии MPS новый запуск завершается исключением без fallback. Гиперпараметры не выбираются по test; validation loss сохраняется после каждой эпохи без изменения обучения, итоговые PNG-метрики относятся к последней эпохе. Экспорт и повторное распространение выполняются на CPU/float64 по прежнему протоколу. Срок и качество достижения сходимости не заданы и не гарантируются.

Перед запуском 50 эпох проверены два полных обновления на MPS с микробатчем 16 и включёнными deterministic algorithms: градиенты конечны. На синтетическом примере после этих обновлений максимальная разность фаз CPU/MPS в float32 составила 3.32e-9 рад при smoke-допуске 1e-3 рад. Это локальная проверка, не гарантия эквивалентности обучающих траекторий. Прогретое второе обновление заняло 0.55 с; скорость всей эпохи следует оценивать по истории фактического запуска.

Каждый запуск создаёт отдельную директорию `results/mnist_10k_<UTC>/`: `parameters.json`, `environment.json`, исходные MNIST, подготовленные PNG, `inputs.json` с контрольными суммами, снимок исходников/документов и git diff, порядок примеров эпохи, `history.json`, checkpoint каждые 5 полных эпох и после последней эпохи с весами/импульсами/RNG (исторические запуски сохраняли каждый batch). `status.json` показывает последний завершённый этап (при аварии нужно также проверить процесс и лог). После обучения для каждого validation/test примера создаются `doe.png`, четыре восстановленных PNG, сырые интенсивности и восемь метрик по протоколу повторного чтения маски; сводки — `validation_metrics.json` и `test_metrics.json`. Исходные цели остаются в `data/`.

Наличие runner и старт процесса сами по себе не означают завершения обучения или подтверждённого качества; фактический статус определяется артефактами запуска.

## Следующий этап: переобучение на одной четвёрке

[experiment_single_sample](../experiment_single_sample/README.md) загружает сохранённый checkpoint и намеренно переобучает все веса на одной фиксированной четвёрке с новым Adam. Архитектура и внутренний GS+Muon адаптер сохраняются; внешний физический оператор учитывает конечные пикселы ДОЭ и детектора на общей физической сетке. Отдельно сравниваются исходный checkpoint, продолжение с прежней формулой loss, комбинированный SSIM/амплитудно-энергетический loss и adjoint-GS. Это новый протокол, не подмена исторических одно-FFT метрик; полный запуск и проверки описаны по ссылке.
